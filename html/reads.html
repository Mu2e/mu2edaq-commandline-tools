Gateway · LID 200

Read run-control state and run information.

Current state

Human and JSON output
mu2edaq-tools otsdaq state
mu2edaq-tools otsdaq state --json

Human output is concise. JSON wraps the server fields in a stable envelope with instance, command, timestamp, and data.

Representative JSON envelope
{
  "command": "state",
  "data": {
    "state": "Running",
    "time_in_state": "184"
  },
  "instance": "crv",
  "timestamp": "2026-07-27T20:00:00+00:00"
}

Run information

Current and historical runs
mu2edaq-tools otsdaq run-info
mu2edaq-tools otsdaq run-info 105504 --json

No run number—or zero—asks for the current run. A positive number requests a historical run.

TFM · LID 302

Inspect artdaq reporting and process state.

CommandUse
daq-reportRead the general DAQ report produced by TFM.
daq-stateRead connection state and per-process artdaq state, decoding embedded JSON fields.
Shell
mu2edaq-tools otsdaq daq-report
mu2edaq-tools otsdaq daq-state
mu2edaq-tools otsdaq daq-state --json

Routing clue: state may work while DAQ calls fail if the Gateway tunnel is open but port 3047 is not forwarded. Configure tfm_url explicitly when necessary.

Macro Maker · LID 800

Discover what is callable—without calling it.

Live inventory
mu2edaq-tools otsdaq macros
mu2edaq-tools otsdaq macros --json

The response includes FE, public, and private macros with permissions, exact input names, and output names. The human view groups those fields into a table.

Runtime is authoritative. DTC interfaces can add forwarding macros for configured child ROCs. The result can be larger than the static 184-macro source inventory and can change after Configure.

Discovery only. The macros command never invokes runFEMacro. Macro execution is outside the Phase 1 typed interface.

Console · Gateway

Read operational messages.

Console messages
mu2edaq-tools otsdaq console
mu2edaq-tools otsdaq console --lcount 100
mu2edaq-tools otsdaq console --watch --interval 1

Console watch mode carries a returned count into the next request. When the server does not supply a recognized cursor, the client advances from the number of returned messages.

Gateway system messages
mu2edaq-tools otsdaq messages
mu2edaq-tools otsdaq messages --history

Automation

Poll for people or stream for scripts.

Every modeled read command accepts --watch, --interval, and --count. Without a count, Ctrl-C stops the loop with status 130.

Human watch
mu2edaq-tools otsdaq state --watch --interval 1
mu2edaq-tools otsdaq pv-read PV_NAME --watch --interval 5
Bounded NDJSON stream
mu2edaq-tools otsdaq daq-state \
  --watch \
  --interval 2 \
  --count 5 \
  --json > daq-state.ndjson
jq examples
mu2edaq-tools otsdaq state --json | jq '.data'

mu2edaq-tools otsdaq state --watch --json |
  jq --unbuffered '.timestamp, .data'

Expert escape hatch

Raw requests are not read-only.

Write-level risk. Raw accepts arbitrary LIDs, RequestTypes, handlers, query parameters, and form fields. It can execute macros, write configuration, restart supervisors, or drive state transitions. The warning is informational, not a guard.

Use raw only after reviewing the RequestType. It does not support watch mode.

Read-oriented example
mu2edaq-tools otsdaq raw getAppStatus --service gateway
mu2edaq-tools otsdaq raw getAppStatus --service gateway --xml
General shape
mu2edaq-tools otsdaq raw SomeRequest \
  --lid 200 \
  --query name=value \
  --form option=value

Normalized JSON is the default. --xml writes the exact server response body.
