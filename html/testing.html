Overview / Testing

Chapter 03

Prove the client without touching a DAQ.

The test harness models three otsdaq origins on local ephemeral ports and validates transport, parsing, CLI behavior, and failures.

On this page

Fake otsdaq harness Python tests C++ regression Package build Platform checks Live smoke test

Test architecture

Three origins, one deterministic fixture.

Gateway group

Models Gateway, Console, Configuration, and Macro Maker LIDs at one origin.

Slow Controls

Uses a separate local origin for PV and alarm JSON-in-XML responses.

TFM

Uses a separate local origin for artdaq report and state responses.

The harness records paths, query fields, form bodies, LIDs, credentials, and request order. Scripted response sequences drive watch-mode tests. It never contacts a live otsdaq instance.

Loopback access required. The tests bind ephemeral 127.0.0.1 ports. Restricted sandboxes may require explicit loopback-socket permission.

Primary suite

Run all Python tests.

Shell
./bootstrap.sh --dev
source venv/bin/activate
pytest -q

The current expected result is:

Expected
51 passed

Run only the otsdaq tests

Focused suite
pytest -q \
  tests/test_otsdaq_settings.py \
  tests/test_otsdaq_client.py \
  tests/test_otsdaq_cli.py

Inspect one test in detail

Verbose output
pytest -vv -s \
  tests/test_otsdaq_cli.py::test_state_json_and_watch_ndjson

The suite covers:

  • Profile selection, URL derivation, and precedence
  • TLS, CA bundles, protected cookie files, and credential scope
  • Correct service origins, LIDs, queries, and form bodies
  • XML normalization, repeated elements, and embedded JSON
  • FE, public, and private macro inventory parsing
  • HTTP, timeout, malformed XML, missing DATA, and server errors
  • Human output, JSON envelopes, NDJSON, watch counts, and raw XML

Regression boundary

Keep the existing C++ surface green.

The otsdaq client is Python-only in Phase 1, but the C++ library and diagnostic executable remain part of the package.

CMake and CTest
cmake -S . -B build -DBUILD_TESTING=ON
cmake --build build
ctest --test-dir build --output-on-failure
Expected
100% tests passed, 0 tests failed out of 2

Distribution check

Confirm the new package ships.

Build a wheel
python3 -m pip wheel \
  --no-deps \
  --no-build-isolation \
  --wheel-dir /tmp/mu2edaq-commandline-tools-wheel \
  .

Expect a wheel named like mu2edaq_commandline_tools-0.2.0-py3-none-any.whl. Its contents must include the mu2edaq_commandline_tools/otsdaq/ package.

Verify Slow Controls
